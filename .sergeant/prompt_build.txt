Fix a UI bug: the stage matrix drops a phase when an agent phase and a code gate share the same name.

Reproduce: a project whose factory.pipeline contains "build" and whose factory.gates contains a gate also named "build" produces two phase records with the same name and different kind (agent vs code). The API returns both. The matrix renders only one, and the surviving cell is whichever was written last.

File: internal/ui/static/index.html, function renderLiveStitchMatrix.

Current cause: columns and cells are keyed by phase name only. The code does roughly byRepo.get(p.repo).set(p.name, p), so the second phase with the same name overwrites the first.

Required fix:
1. Key cells by the pair (kind, name) so an agent phase and a code gate with the same name both survive and both render.
2. Column identity must also be that pair. Keep the plain phase name as the visible column label when that name is unique across kinds. Only when the same name appears with two different kinds, disambiguate the labels, for example "build (agent)" and "build (gate)".
3. Preserve first-seen ordering of columns.
4. Do not change any other rendering behaviour.

Write the test as a Go test if you can assert the rendering logic without a browser; otherwise add a small node script under /tmp/sergeant-e2e and describe in your summary exactly how you verified that both a build/agent phase and a build/code phase render as separate columns.
