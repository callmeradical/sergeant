Implement enforced TDD red-to-green evidence for a bullet, per decision D3 in docs/prd-sergeant-v2.md. Read AGENTS.md first.

D3 states: a bullet must record a FAILING gate result before implementation and a PASSING one after. Red-to-green is evidence produced by deterministic gates with no model judgment. Bullets with no natural red state (pure refactor) require an explicit, recorded exemption.

Scope this to internal/dag and internal/store only. Do not touch the UI.

Work to do:

1. In internal/dag/engine.go add an exported function with this shape:

     type GateEvidence struct {
         Gate     string
         Status   string   // "failed" or "passed"
         Stage    string   // "red" or "green"
         Output   string
         Duration time.Duration
     }

     func (e *Engine) RecordRedState(ctx context.Context, runID, repoName string) ([]GateEvidence, error)
     func (e *Engine) RecordGreenState(ctx context.Context, runID, repoName string) ([]GateEvidence, error)

   RecordRedState runs the repo configured gates in sorted name order and REQUIRES at
   least one to fail. If every gate passes it returns an error explaining that no red
   state was observed, because that means the work was not test-first.
   RecordGreenState runs the same gates and REQUIRES all of them to pass.

   Both record a phase per gate via the store, with Kind "code" and a Name that makes the
   stage visible, for example "red:test" and "green:test". Reuse the existing gate
   execution path in internal/runner rather than shelling out separately.

2. Add an exemption path. A bullet with no natural red state must be able to record an
   explicit, durable exemption rather than silently skipping. Implement:

     func (e *Engine) RecordRedExemption(ctx context.Context, runID, repoName, reason string) error

   It must refuse an empty reason. It records the exemption as a phase so it appears in
   the run record and cannot be invisible.

3. Tests in internal/dag/engine_test.go:
   - red state satisfied: a repo whose gate fails initially returns evidence with
     Stage "red" and no error
   - red state violated: a repo whose gates all pass returns an error mentioning that no
     failing gate was observed
   - green state: after the gate is made to pass, RecordGreenState returns passing
     evidence and no error
   - exemption requires a reason: empty reason returns an error
   - exemption is recorded: a valid reason creates a phase record
   Use the existing helpers in that test file (newGitRepo, newEngine, SERGEANT_FLEET_DIR
   via t.Setenv) so tests never touch the real fleet path. Drive gate pass/fail by
   writing a small shell gate command in the temp repo, for example a gate that runs a
   script you can flip from exit 1 to exit 0.
